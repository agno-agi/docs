Dash gives its Analyst and Engineer the same `Knowledge` instance and enables the `search_knowledge_base` tool.

```python
from agno.agent import Agent
from agno.knowledge import Knowledge
from agno.knowledge.embedder.openai import OpenAIEmbedder
from agno.vectordb.pgvector import PgVector, SearchType

dash_knowledge = Knowledge(
    name="Dash Knowledge",
    vector_db=PgVector(
        db_url=DB_URL,
        table_name="dash_knowledge",
        search_type=SearchType.hybrid,
        embedder=OpenAIEmbedder(id="text-embedding-3-small"),
    ),
)

analyst = Agent(
    knowledge=dash_knowledge,
    search_knowledge=True,
)
```

Demo OS also configures a contents database so it can track the source content separately from the vector index.

## Loading content

Dash loads table descriptions, validated queries, and business rules from `agents/dash/knowledge/`:

```bash
python -m agents.dash.scripts.load_knowledge
```

Pass `--recreate` to drop and rebuild the vector table. The default run inserts or updates the three knowledge directories.

You can also insert content directly:

```python
dash_knowledge.insert(
    name="MRR definition",
    text_content="MRR is the sum of active subscriptions excluding trials.",
    metadata={"category": "business_rules"},
)
```

## Hybrid search

PgVector hybrid search combines two scores:

| Signal | Implementation |
|--------|----------------|
| Semantic similarity | Vector distance against the configured embeddings |
| Keyword relevance | PostgreSQL full-text search with `to_tsvector` and `ts_rank_cd` |

PgVector normalizes the text rank and combines it with the vector score using `vector_score_weight`. The default gives each signal a weight of `0.5`. This path uses weighted scoring. BM25 and reciprocal rank fusion use different scoring algorithms.

## When Dash searches

`search_knowledge=True` adds `search_knowledge_base(query)` to each specialist. Dash does not set `add_knowledge_to_context`, so AgentOS does not run a knowledge search automatically before every response.

The Analyst and Engineer instructions tell the model to search first. The model decides when to call the tool, and tool use remains model-driven.

## Metadata filters

Metadata attached during ingestion can filter a search:

```python
dash_knowledge.search(
    query="How do we calculate MRR?",
    filters={"category": "business_rules"},
)
```

Use filters for tenant, topic, or document-type boundaries when those fields are present in the stored metadata.

## Reranking

Dash does not configure a reranker. To add one, set the candidate count on `Knowledge` and the output limit on the reranker:

```python
from agno.knowledge.reranker.cohere import CohereReranker

knowledge = Knowledge(
    max_results=20,
    vector_db=PgVector(
        table_name="company_knowledge",
        db_url=DB_URL,
        search_type=SearchType.hybrid,
        reranker=CohereReranker(
            model="rerank-multilingual-v3.0",
            top_n=5,
        ),
    ),
)
```

This configuration retrieves up to 20 candidates and then returns at most 5 reranked documents. Without `top_n`, the reranker reorders the retrieved candidates without reducing their count. `Knowledge.max_results` defaults to 10.
