Dash exposes its curated SQL knowledge as a tool for the Analyst and Engineer.

```python
analyst = Agent(
    id="analyst",
    knowledge=dash_knowledge,
    search_knowledge=True,
    tools=build_analyst_tools(dash_knowledge),
    instructions=build_analyst_instructions(),
)
```

The Analyst instructions require a knowledge search before writing SQL. `search_knowledge=True` supplies the tool. The model still decides whether to call it.

## What Dash stores

Dash loads three knowledge directories into one `Knowledge` instance:

| Directory | Contents |
|-----------|----------|
| `tables/` | Table descriptions, columns, value ranges, and data notes |
| `queries/` | Validated SQL patterns |
| `business/` | Metric definitions and business rules |

```bash
python -m agents.dash.scripts.load_knowledge
```

Pass `--recreate` to drop and rebuild the vector table.

## Retrieval flow

For a data question, the intended flow is:

1. The Dash leader delegates the question to the Analyst.
2. The Analyst calls `search_knowledge_base` for table metadata, query patterns, and business rules.
3. PgVector ranks documents with a weighted combination of vector similarity and PostgreSQL full-text relevance.
4. The Analyst writes and executes SQL through its database connection, which should use a SELECT-only PostgreSQL role.
5. The Analyst interprets the results and returns them to the leader.

Dash does not set `add_knowledge_to_context`. Retrieval is a model-selected tool call rather than an automatic search on every message. The prompt directs the search, but the runtime does not guarantee that the model will call the tool.

## Hybrid scoring

`SearchType.hybrid` combines semantic and keyword signals:

| Signal | Source |
|--------|--------|
| Vector score | Cosine similarity by default |
| Text rank | PostgreSQL `ts_rank_cd` over `to_tsvector` |

The two normalized scores are combined using `vector_score_weight`, which defaults to `0.5`. This path uses weighted scoring. BM25 and reciprocal rank fusion use different scoring algorithms.

## What retrieval changes

Knowledge search gives the Analyst source material for questions such as:

| Question | Relevant knowledge |
|----------|--------------------|
| "What's our MRR trend?" | MRR definition, subscription schema, validated revenue query |
| "Why is churn increasing?" | Churn rules, lifecycle fields, prior query patterns |
| "Show revenue by plan" | Plan and subscription metadata, aggregation examples |

Retrieved context can reduce invalid columns and incorrect metric definitions. SQL correctness still depends on model tool use, the stored material, and the database result.

Add reranking by configuring the vector database. The retrieval candidate limit comes from `Knowledge.max_results`, which defaults to 10. A reranker's `top_n` can reduce that candidate set. See [Knowledge](/demo-os/knowledge#reranking) for the configuration.
