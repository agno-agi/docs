Clinic passes two callable dependencies to its team and member agents:

```python
from typing import Any

from agno.team import Team

from teams.clinic.context import get_patient_context
from teams.clinic.patients import patient_id_for


def current_patient_id(run_context: Any) -> str:
    return patient_id_for(getattr(run_context, "user_id", None))


dependencies = {
    "patient_appointments": get_patient_context,
    "current_patient_id": current_patient_id,
}

clinic = Team(
    id="clinic",
    dependencies=dependencies,
    add_dependencies_to_context=True,
    # ...
)
```

Agno resolves each callable for the current run. The callable receives `run_context`, so Clinic can derive a patient ID from `run_context.user_id` and query the current patient's appointments.

```python
def get_patient_context(run_context: Any) -> str:
    patient_id = patient_id_for(getattr(run_context, "user_id", None))

    with _engine.connect() as conn:
        rows = conn.execute(
            text(
                "SELECT a.appt_date, a.appt_time, p.name, p.specialty, "
                "a.reason, a.status "
                "FROM clinic.appointments a "
                "JOIN clinic.providers p USING (provider_id) "
                "WHERE a.patient_id = :pid AND a.status = 'scheduled' "
                "ORDER BY a.appt_date, a.appt_time"
            ),
            {"pid": patient_id},
        ).fetchall()

    # Format the rows as context for the model.
```

`add_dependencies_to_context=True` adds the resolved values to the model context. Clinic provides the same dependency mapping to the team leader, Scheduling Coordinator, and Medical Records Specialist.

## Dependency roles

| Dependency | Result | Consumer |
|------------|--------|----------|
| `patient_appointments` | Formatted upcoming appointments from live SQL | Team leader and members |
| `current_patient_id` | Patient ID mapped from `run_context.user_id` | Provided to the Medical Records Specialist so it can select a knowledge filter |

The scheduling tools also read `run_context.user_id` directly before querying appointment rows. Provider availability and formulary queries are shared clinic data and do not use a patient ID.

<Warning>
  The Demo OS mapping accepts known usernames or raw IDs beginning with `P-`. Missing and unknown users map to the sample patient `P-1002`. Treat this as sample data routing. Production applications should derive the patient ID from an authenticated identity and enforce database and document access independently of model instructions.
</Warning>
